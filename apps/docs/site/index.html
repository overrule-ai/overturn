WHAT THIS MEANS

Regressions are cases a human already approved

An approved answer that now comes back different is the only thing that should block a deploy, so the report lists those first, side by side with the baseline and the human's decision. Everything else — fixed, still wrong — comes after.

Nothing fired twice

Every tool call in a replay is answered from the recording, matched by fingerprint rather than position. A model that takes a different path still gets the right answers; a tool with side effects is refused. The receipt at the bottom of each report says exactly what was and wasn't tested.

Scored on the fields the human changed

An edit that touched priority is scored on priority, so rephrasing a structured answer isn't a regression. Free-text answers are scored by a judge model, and the report says which model judged.

Five API endpoints

Record runs, attach corrections, start replays, read the report. The SDKs and CLI call the same API you can.

API reference →

POST /v1/runsa recorded run: prompts, tool calls with their results, the final answer
POST /v1/correctionsapprove, edit, reject or escalate a run — it becomes a case with the fix attached
POST /v1/replaysreplay every case against a model and prompt version; pass several models for a matrix
GET /v1/replays/{id}the report: regressions first, then fixed and still-wrong, with the receipt of what was tested
POST /v1/tracesOTLP/HTTP — spans with gen_ai.* attributes become runs, no SDK required

What Overturn handles

Cases from real corrections

Not hand-written datasets. Every approve, edit, reject or escalate on a real run becomes a case, with the human's answer attached.

Safe replay

Tool calls are matched to recordings by fingerprint, so a model that takes a different path still gets the right answers. Nothing is emailed, refunded or written twice.

Can a cheaper model do the job?

Replay the same suite against several models at once and read them side by side: pass rate, regressions and cost per run, scored on your team's own corrections.

Prompt versions

Prompts are versioned on first sight. Replay v3 against the cases recorded under v2 before you ship it.

Decision fields

Scoring looks at the fields the human changed, not the phrasing. A judge model handles free text, and says which model it used.

Review in Slack

New runs that need a decision post to a channel with Review and Approve buttons. One click, one case.

CorrectButton for your own UI

A React component and a one-line handler that turn the "fix this" button you already have into corrections, without changing your data model.

Deployment options

Self-hosting guide →

Every deployment runs the same code. The hosted app is free during the open beta. Self-hosting needs one Postgres with pgvector and the two containers; the SDKs only change a base URL.

Hostedapp.overturn.run. Sign in with email, create a key, send the first run. We run Postgres and the replay workers.
Self-hosteddocker compose up on any box with Postgres 16. Your recordings never leave your network; model calls go straight to the provider with your keys.
Air-gappedPoint the replay at a local model endpoint (any OpenAI-compatible server). No outbound traffic is required.

Already sending OpenTelemetry?

Point any OTLP/HTTP exporter at the endpoint below with your key in the authorization header. Spans with gen_ai.* attributes become model steps; tool spans with results become recordings. OpenLLMetry, Traceloop, the OpenAI and Anthropic instrumentations and LangSmith's export are verified.

Frequently
asked questions

01What do I send?⌄
Runs. A run is the input, every prompt and model answer, every tool call with its result, and the final output. The SDK records all of it with one wrapper; OpenTelemetry users send the spans they already have.
02What comes back?⌄
A report per replay: regressions first (approved cases that now fail), then fixed cases, then still-wrong ones, each with the baseline, the new answer and the human's decision side by side, plus a receipt listing exactly which tool calls were answered from the recording.
03How is this different from evals or Braintrust?
Evals start from a dataset somebody has to write and keep current. Overturn's cases come from the corrections your reviewers already make, so the suite grows with production and tests the things that actually went wrong. Replays are also safe: tools are answered from the recording, never re-executed.
04What happens to tools with side effects?⌄
They're answered from the recording when the call matches a recorded fingerprint, and refused when it doesn't. Nothing is emailed, refunded or written during a replay. The receipt says which calls were refused so you can tell what wasn't tested.
05Which models and frameworks?⌄
Recording: OpenAI, Anthropic and the Vercel AI SDK in TypeScript; OpenAI and Anthropic in Python; anything that emits OpenTelemetry gen_ai spans. Replay: OpenAI, Anthropic, Google, OpenRouter, or any OpenAI-compatible endpoint, including local models.
06How much does it cost?⌄
Nothing during the open beta. Self-hosting is free forever under Apache-2.0. Replays call the model providers with your own keys, so you pay them directly — a 25-case replay on a small model costs a few cents.
07Where does my data live?⌄
Hosted: in one Postgres on Railway (US), encrypted at rest, raw runs purged after 30 days unless a case depends on them. Self-hosted: wherever you put it. Model calls during replay go straight from the replay worker to the provider.
